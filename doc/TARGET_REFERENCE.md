# 목표 게임 레퍼런스

## 핵심 감각

- 접속하면 전투가 이미 진행 중이어야 한다.
- 화면 상단은 재화와 현재 진행 정보를 보여준다.
- 중앙은 자동전투, 드랍, 데미지 숫자, 스테이지 진행을 보여준다.
- 하단은 성장, 영웅, 소환, 던전, 아레나, 상점 같은 주요 메뉴를 고정한다.
- 성장 화면은 리스트형이며, 각 항목은 아이콘, 레벨, 수치, 레벨업 버튼을 가진다.
- 버튼과 정보량은 많아도 된다. 이 장르는 깔끔한 미니멀 UI보다 반복 성장 조작의 접근성이 중요하다.

## 그대로 베끼면 안 되는 것

- 원본 캐릭터 디자인
- 원본 UI 아이콘
- 원본 배경/이펙트
- 원본 명칭과 로고
- 원본 배치의 픽셀 단위 복제

참고해야 할 것은 시스템 구조와 UX 밀도다.

## 성장 능력치

골드를 쓰는 계정 능력 성장은 다음 7개를 기준으로 한다. 현재 MVP 구현 기준으로는 모두 UI와 계산에 연결한다.

| ID | 이름 | 설명 | 1차 MVP 반영 |
| --- | --- | --- | --- |
| attackPower | 공격력 | 기본 데미지 증가 | 예 |
| maxHp | 체력 | 영웅 최대 체력과 전투력 증가 | 예 |
| criticalChance | 치명타 확률 | 일정 확률로 치명타 발생 | 예 |
| criticalDamage | 치명타 데미지 | 치명타 배율 증가 | 예 |
| doubleCriticalChance | 더블 치명타 확률 | 치명타 발생 후 추가 확률로 더블 치명타 발생 | 예 |
| doubleCriticalBonusDamage | 더블 치명타 추가 데미지 | 더블 치명타 발생 시 추가 배율 | 예 |
| finalDamage | 최종 데미지 | 모든 계산 후 최종 배율 증가 | 예 |

치명타 확률과 더블 치명타 확률은 최대 50% 제한이 있으므로 레벨 상한이 짧다. 대신 비용 곡선을 높게 잡아야 한다. 초반에 확률 계열을 너무 쉽게 MAX로 만들면 이후 데미지 성장 체감이 급격히 무너진다.

## 데미지 계산 방향

최종 목표 계산식은 아래 구조를 따른다.

```text
기본 데미지 = 영웅 공격력 + 능력 공격력 보너스
치명타 적용 데미지 = 기본 데미지 * 치명타 데미지 배율
더블 치명타 적용 데미지 = 치명타 적용 데미지 * 더블 치명타 추가 배율
최종 데미지 = 적용 데미지 * 최종 데미지 배율
```

주의점:

- 치명타와 더블 치명타를 너무 일찍 넣으면 데미지 편차가 커져 보스 밸런스가 흔들린다.
- `최종데미지`는 가장 강한 증가 항목이므로 초반 성장 항목으로 싸게 제공하면 밸런스가 빠르게 망가진다.
- `체력`은 적 공격과 영웅 HP가 들어간 뒤부터 의미가 있다. 지금은 생존 압박의 시작점으로만 쓰고, 전투 실패/부활/방어 스킬까지 붙은 뒤에 최종 밸런스를 다시 잡는다.

## 계정 레벨과 특성

특성은 골드 성장과 다른 축이다. 전투 보상으로 계정 경험치를 얻고, 계정 레벨이 오를 때마다 특성 포인트 1점을 받는다. 이 포인트를 영웅 탭의 `특성` 하위 탭에서 사용한다.

초기 특성 트리는 19개 뎁스를 가로로 진행하는 연결형 트리다. 뎁스별 노드 수는 `1, 3, 3, 1, 2, 2, 1, 3, 3, 2, 1, 2, 1, 3, 3, 3, 1, 2, 1`이다.

| 효과군 | 역할 |
| --- | --- |
| 전투 | 공격력, 치명타 데미지, 최종 데미지, 스킬 데미지 |
| 생존 | 체력, 받는 피해 감소, 이동속도 |
| 보상 | 골드 획득량, 경험치책 획득량, 계정 경험치 획득량 |

같은 뎁스가 아니라 선으로 직접 연결된 이전 뎁스 노드 중 하나를 MAX까지 찍어야 다음 노드가 열린다. 이 구조는 장기 성장 잠금을 만들기 위한 최소 장치다. 다만 모든 노드가 100레벨이면 몇 년 운영 기준으로는 여전히 얕다. 운영형 게임으로 키우려면 계정 레벨 상한 확장, 시즌/프레스티지형 재분배 구조, 특성 초기화 비용 설계가 필요하다.

| eventSummonTicket | 이벤트 뽑기권 | 이벤트 뽑기 |
| heroSummonTicket | 영웅 뽑기권 | 영웅 뽑기 |
| sealSummonTicket | 룬 뽑기권 | 룬 뽑기 |
| equipmentSummonTicket | 장비 뽑기권 | 장비 뽑기 |
| accountExperience | 계정 경험치 | 계정 레벨과 특성 포인트 획득 |

중요한 수정:

- 영웅 레벨업은 골드가 아니라 `영웅 경험치 아이템`으로 한다.
- 골드는 계정 능력 성장에 먼저 사용한다.
- 뽑기는 전용 뽑기권을 먼저 소모하고, 뽑기권이 없을 때 루비를 소모한다.
- 계정 경험치는 소모 재화가 아니라 누적 성장값이다. 계정 레벨업으로 특성 포인트를 지급한다.

## 뽑기 비용 규칙

```text
뽑기권 보유 수량 >= 요청 횟수
→ 뽑기권 소모

뽑기권 부족
→ 부족한 횟수만큼 루비 비용 계산
→ 루비가 충분하면 루비 소모
→ 루비도 부족하면 뽑기 불가
```

1회, 10회, 100회 같은 다중 뽑기는 나중에 넣는다. 1차 MVP에서는 1회와 10회만 있으면 충분하다.

## 성장 화면 방향

성장 화면은 아래 리스트 구조를 따른다.

```text
능력 총 전투력
배율 선택: 1x / 10x / 100x / 1000x

능력 항목 1
  아이콘
  현재 레벨
  능력 이름
  현재 수치
  레벨업 비용 또는 MAX

능력 항목 2
...
```

현재 구현 기준 성장 항목은 아래 7개다.

- 공격력 증가
- 체력 증가
- 치명타 확률 증가
- 치명타 데미지 증가
- 더블 치명타 확률 증가
- 더블 치명타 추가 데미지 증가
- 최종 데미지 증가

성장 단위 버튼은 `1x`, `10x`, `100x`, `1000x`다. 단위 선택은 항상 가능하고, 실제 구매 비용이 부족하면 해당 성장 행을 회색으로 보이게 한 뒤 클릭 시 `골드가 부족합니다.` 문구를 띄운다.

## 1차 MVP에 반영할 것과 미룰 것

### 바로 반영

- 재화에 `루비`, `영웅 경험치 아이템`, 뽑기권 개념 추가
- 영웅 레벨업 비용을 골드에서 영웅 경험치 아이템으로 변경
- 영웅/장비 뽑기권과 루비 대체 소모 구조
- 영웅 중복 뽑기 시 조각 1개 지급
- 장비 뽑기, 장비 레벨/성급/분해/장착 UI
- 능력 성장 7종과 계정 특성 트리
- 계정 레벨, 계정 경험치, 특성 포인트 저장
- 토템 전역 성장축
- 룬 프리셋 장착/합성
- 요새 단일 레벨 성장
- 시설 파견

### 뒤로 미룸

- 100회, 1000회 뽑기
- 이벤트 픽업
- 장비 세트 효과와 전투 밸런스 최종 반영
- 특성 프레스티지/초기화
- 원본 수준의 이펙트와 데미지 숫자 연출

## 냉정한 판단

현재는 메뉴 수보다 밸런스 검증이 더 큰 리스크다. 성장 7종, 장비, 초월, 특성이 동시에 열리면 수치가 너무 빨리 튈 수 있다. 구현 자체보다 각 성장축이 서로 다른 시간을 먹도록 비용 곡선을 분리하는 게 중요하다.

다음 구현 순서는 새 메뉴 추가보다 검증 루프 쪽이 맞다.

```text
1. 1-1부터 1-20까지 실제 플레이 시간과 막힘 지점 측정
2. 골드 성장, 영웅 레벨, 장비, 특성의 기여도를 분리해 리포트화
3. 초반 30분, 2시간, 1일 기준 보상량 조정
4. 전장 캐릭터 가독성과 UI 폰트 크기 조정
5. 그 다음 던전, 장비 세트, 프레스티지 같은 새 성장축 확장
```
