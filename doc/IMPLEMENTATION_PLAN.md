# Unity 구현 계획

## 개발 원칙

- 먼저 자동 진행과 보스 막힘 규칙을 만든다.
- 그래픽은 임시 도형과 텍스트로 시작한다.
- 모든 주요 수치는 코드에 박아 넣지 않고 데이터로 분리할 수 있게 설계한다.
- 1차 MVP에서는 온라인 기능을 넣지 않는다.

## 권장 Unity 설정

- Unity 버전: LTS 버전 사용
- 템플릿: 2D 또는 Universal 2D
- 화면 방향: Portrait
- 목표 빌드: Android
- 입력: 터치와 마우스 클릭 모두 대응

## 1단계: 프로젝트 기본 구성

완료 기준:

- Unity 프로젝트 열기
- 세로 화면 Game View 설정
- `Main` 씬 생성 또는 `SampleScene`을 `Main`으로 변경
- 기본 UI Canvas 생성
- 상단 골드/스테이지/진행 모드 영역 배치
- 중앙 전투 영역 배치
- 하단 메뉴를 성장, 히어로, 소환, 던전 배틀, 상점 순서로 배치

## 2단계: 데이터 정의

완료 기준:

- `HeroData` 정의
- `EnemyData` 정의
- `BossData` 정의
- `StageData` 정의
- `ProgressMode` enum 정의
- 영웅 5명 데이터 입력
- 일반 적 5종 데이터 입력
- `1-20` 보스 1종 데이터 입력
- `1-1`부터 `1-20`까지 스테이지 데이터 입력

초기에는 코드 배열로 시작해도 된다. 단, 스테이지와 적 데이터는 빠르게 늘어나므로 구현이 안정되면 ScriptableObject로 옮기는 것이 낫다.

## 3단계: 스테이지 진행 시스템

완료 기준:

- 현재 스테이지 ID를 관리한다.
- 최고 도달 스테이지 ID를 관리한다.
- 진행 모드를 관리한다.
- 일반 스테이지 클리어 시 자동 진행 모드에서는 다음 스테이지로 이동한다.
- 선택 반복 모드에서는 같은 스테이지를 다시 시작한다.
- 보스 실패 시 `BossBlocked` 모드로 바꾸고 `1-19`로 이동한다.
- 자동 진행 재개 버튼을 누르면 최고 진행 위치 기준으로 다시 진행한다.

## 4단계: 자동전투

완료 기준:

- 전투 시작 시 현재 스테이지 타입에 맞는 적 또는 보스 생성
- 영웅 5명이 각자의 공격 주기마다 적 HP 감소
- 적 HP UI 표시
- 일반 적 사망 시 골드 지급
- 일반 적 처치 수 카운트
- 처치 할당량 달성 시 `StageProgressManager`에 클리어 통보
- 보스 스테이지에서는 30초 타이머 작동
- 보스 처치 성공과 시간 초과 실패를 구분

## 5단계: 골드와 레벨업

완료 기준:

- 골드 보유량 표시
- 영웅별 레벨 표시
- 영웅별 등급, 성급, 조각 표시
- 영웅별 공격력 표시
- 레벨업 버튼 구현
- 히어로 경험치 아이템이 부족하면 레벨업 불가
- 조각이 충분하면 성급업 가능
- 레벨업 후 보스 처치 가능성이 체감 가능하게 상승

## 6단계: 스테이지 선택 UI

완료 기준:

- `1-1`부터 최고 도달 스테이지까지 선택 가능
- 선택한 일반 스테이지는 반복 파밍 모드로 실행
- 선택한 보스 스테이지는 보스 재도전으로 실행
- 현재 모드가 자동 진행인지 반복 파밍인지 화면에 표시
- 자동 진행 재개 버튼 제공

1차 MVP에서는 스테이지 목록을 간단한 버튼 목록으로 처리한다. 맵 연출은 제외한다.

## 7단계: 뽑기

완료 기준:

- 1회 뽑기 버튼
- 10회 뽑기 버튼
- 확률에 따라 언커먼, 레어, 에픽, 전설, 신화 결과 출력
- 등급에 맞는 영웅 중복 조각 지급
- 영웅별 조각 수와 성급 표시

주의:

뽑기를 캐릭터 해금 시스템으로 만들면 예외 처리가 늘어난다. 1차 MVP에서는 모든 영웅을 기본 보유시키고, 뽑기는 조각 획득으로 제한하는 편이 낫다.

## 8단계: 로컬 저장

완료 기준:

- 골드 저장
- 최고 도달 스테이지 저장
- 현재 스테이지 저장
- 선택 스테이지 저장
- 진행 모드 저장
- 보스 클리어 여부 저장
- 영웅 레벨 저장
- 영웅 조각 저장
- 영웅 성급 저장
- 재실행 후 데이터 복원

## 9단계: 오프라인 보상

완료 기준:

- 종료 또는 백그라운드 진입 시 마지막 접속 시간 저장
- 재접속 시 시간 차이 계산
- 최대 8시간까지만 보상 계산
- 현재 파밍 스테이지 기준으로 보상 계산
- 현재 위치가 보스면 직전 일반 스테이지 기준으로 보상 계산
- 오프라인 보상 팝업 표시
- 수령 시 골드 증가

## 확장 방향 반영 작업

이번 방향 변경은 다음 순서로 반영한다.

```text
1. 실제 전투 배속 시스템 추가 - 1x/2x 무료, 4x 권한 플래그
2. 일반 스테이지 처치 목표를 100마리로 변경
3. 영웅 데이터를 5명으로 확장
4. 자동 발동 스킬 데이터와 전투 계산 추가
5. 기본 장착 펫 1마리와 자동 공격 추가
6. 전장, 배속 버튼, 지원 탭 UI 추가
7. 영웅 등급, 중복 조각, 성급업 구조 추가
8. 성장/뽑기/스테이지 알림 빨간 점과 사이드 아이콘 레일 추가
9. 도형 기반 임시 전투 액터, 중앙 영웅 진형, 사방 외곽에서 몰려오는 몬스터 이동, 영웅 공격 모션 추가
10. 성장 7종, 종합 전투력, 1x/10x/100x/1000x 레벨업 UI 추가
11. 레퍼런스형 중앙 스테이지 배지, 가이드 퀘스트, 데미지 미터기 오버레이 추가
12. QA 러너와 밸런스 리포트 갱신
```

4배속 결제, 수동 스킬, 펫 성장, 몬스터 100개 실제 오브젝트 생성은 아직 구현하지 않는다.

## 10단계: MVP QA

확인할 항목:

- 첫 실행에서 오류 없이 `1-1` 자동전투가 시작되는가
- `1-1` 몬스터 100마리 처치 후 `1-2`로 자동 이동하는가
- 일반 스테이지 선택 시 같은 스테이지만 반복하는가
- 보스 스테이지에서 30초 타이머가 작동하는가
- 보스 실패 시 `1-19` 반복 파밍으로 돌아가는가
- 자동 진행 재개 시 다시 보스 도전이 가능한가
- 골드가 음수가 되지 않는가
- 저장 후 재실행해도 진행 모드와 스테이지가 유지되는가
- 기기 시간을 조작했을 때 오프라인 보상이 비정상적으로 커지지 않는가

## 리스크

| 리스크 | 이유 | 대응 |
| --- | --- | --- |
| 보스 실패 구조가 없으면 성장 목표가 약함 | 유저가 왜 파밍해야 하는지 명확하지 않음 | `1-20` 보스 관문을 MVP에 반드시 포함 |
| 선택 스테이지 반복과 자동 진행이 섞임 | 상태 관리가 꼬이면 진행 버그가 쉽게 생김 | `ProgressMode`를 명시적으로 둔다 |
| 밸런스가 너무 빠르게 무너짐 | 방치형은 수치 증가가 핵심이라 작은 공식 차이가 크게 벌어짐 | 챕터 1만 먼저 조정 |
| UI 작업량 증가 | 수집 RPG는 버튼, 팝업, 목록이 많음 | 1차 MVP는 한 화면 중심으로 제한 |
| 뽑기 복잡도 증가 | 천장, 픽업, 중복, 등급 연출이 붙으면 커짐 | 등급 확률, 조각, 성급업까지만 구현 |
| 저장 구조 재작업 | PlayerPrefs는 확장성이 낮음 | MVP 이후 JSON 저장으로 이전 |

## 다음 결정 사항

아직 결정해야 할 것은 다음이다.

- 보스 실패 후 자동 재도전 버튼을 둘지, 자동 진행 재개 버튼만 둘지
- 스테이지 선택 UI를 목록형으로 할지, 간단한 챕터 맵으로 할지
- 영웅 비주얼 방향: 임시 도형, 픽셀, SD 캐릭터 중 선택
- 게임명
- 세계관 톤: 판타지, 현대, SF 중 선택

이 결정들은 1차 MVP 구현을 막지는 않는다.

## 레퍼런스 반영 후 수정된 우선순위

새 레퍼런스 기준으로 성장과 뽑기 구조가 확장되었다. 하지만 전부 바로 구현하면 MVP가 흐려진다.

다음 구현에서는 아래 순서만 반영한다.

```text
1. CurrencyWallet을 gold, ruby, heroExpItem, heroSummonTicket 지원으로 확장 - 완료
2. 히어로 레벨업 비용을 gold에서 heroExpItem으로 변경 - 완료
3. 전투 보상에 heroExpItem 소량 지급 추가 - 완료
4. 계정 능력 성장 데이터 추가 - 완료
5. 공격력, 체력, 치명타, 더블 치명타, 최종 데미지 성장 7종으로 확장 - 완료
6. 성장 레벨업 단위를 1x/10x/100x/1000x로 선택 가능하게 변경 - 완료
7. 히어로 뽑기는 heroSummonTicket 우선, 부족하면 ruby 소모로 변경 - 완료
```

이벤트 뽑기, 인장 뽑기, 장비 뽑기는 구조만 고려하고 실제 구현은 히어로 뽑기 루프가 안정된 뒤에 한다.
