# 룬 슬롯 구현 메모

- 슬롯 해금 기준은 `GameData.GetRuneSlotUnlockLevel`에서 관리한다.
- UI는 잠긴 슬롯을 `잠금 / Lv.X`로 표시하고 클릭 시 해금 조건을 안내한다.
- `BattleManager.GetActiveUsableRune`은 잠긴 슬롯을 무시하므로 예전 저장값이 있어도 전투 효과가 적용되지 않는다.
- 룬은 `RuneGrade`와 등급별 보유 수량 `rune.{runeId}.count.{grade}`를 저장한다. 레벨 기반 강화와 룬조각/룬가루 재화는 사용하지 않는다.
- 기존 `RuneLevel` 저장값은 최초 로드 시 등급 추정에만 사용한다.
- `TryPromoteRune`, `TryPromoteAllRunes`, `DebugAddRuneItems`가 룬 합성 흐름의 진입점이다.

# 편성 장착 구현 메모

- 편성 탭은 영웅 8슬롯과 룬 4슬롯을 한 화면에서 관리한다.
- 토템 장착 슬롯은 폐기한다. 토템은 영웅 하단 `토템` 탭에서 강화하고 6종 효과가 항상 전체 적용된다.
- 룬 2~4번 슬롯은 `GameData.GetRuneSlotUnlockLevel`의 계정 레벨 조건을 따른다.
- 잠긴 슬롯은 `잠금 / Lv.X`를 표시하고, 클릭하면 해금 레벨 안내만 띄운다.
- 룬 슬롯 클릭 시 현재 편성 화면 위에 룬 목록 모달을 띄운다.
- 토템 탭은 선택, 강화/전체 진화, 정보 확인용으로 유지하고 장착 버튼과 `+` 액션은 만들지 않는다.
- 영웅, 룬 변경은 `editingFormationHeroIds`, `editingFormationRuneIds`에 임시 보관한다.
- 편성 탭을 나가거나 닫을 때 dirty 상태면 저장 확인 팝업을 띄운다.
- 확인 시 `BattleManager.ApplyHeroFormationLoadout`으로 영웅/룬을 한 번에 저장하고 `StartStage()`로 현재 스테이지를 다시 시작한다.
- 취소 시 임시 편성을 폐기하고 저장된 프리셋 데이터를 다시 로드한다.
- 저장 전 임시 룬 변경은 전투 계산에 반영하지 않는다.

# 메뉴 패널 구현 메모

- `activeTab == Growth`일 때만 `contentRoot`가 레이아웃 높이를 차지한다.
- 그 외 메뉴는 `contentLayoutElement.ignoreLayout = true`로 전환해 전투 화면 위에 오버레이한다.
- 하단 탭은 유지해야 하므로 오버레이 패널의 하단 오프셋은 130px로 둔다.

# 현재 구현 기준

- 하단 대메뉴는 `성장, 영웅, 요새, 시설, 소환, 배틀, 상점` 순서다.
- 영웅 하위 탭은 `편성, 특성, 토템, 룬`이다. 시설은 영웅 하위 탭이 아니라 별도 대메뉴다.
- 토템은 장착 슬롯을 완전히 폐기한 전역 성장축이다. 토템 탭에는 선택, 효과 확인, 강화/전체 진화만 둔다.
- 룬은 프리셋별 4칸 장착물이다. 영웅/룬 편성 변경은 저장 확인 후 반영하고 스테이지를 다시 시작한다.
- 요새는 Lv.1~300 단일 레벨 성장축이다. 요새 경험치는 누적 기준이며 레벨업 시 소모하지 않는다.
- 시설 파견은 6종 시설, 12시간 누적 생산, 영웅 배치, 사냥 자재 업그레이드를 가진 별도 대메뉴다.

## 1단계: 프로젝트 기본 구성

완료 기준:

- Unity 프로젝트 열기
- 세로 화면 Game View 설정
- `Main` 씬 생성 또는 `SampleScene`을 `Main`으로 변경
- 기본 UI Canvas 생성
- 상단 골드/스테이지/진행 모드 영역 배치
- 중앙 전투 영역 배치
- 하단 메뉴를 성장, 영웅, 요새, 시설, 소환, 배틀, 상점 순서로 배치

## 2단계: 데이터 정의

완료 기준:

- `HeroData` 정의
- `EnemyData` 정의
- `BossData` 정의
- `StageData` 정의
- `ProgressMode` enum 정의
- 영웅 38명 데이터 입력 - 커먼~전설 6명씩, 신화는 8명 이상 확장 가능
- 일반 적 5종 데이터 입력
- 챕터 보스 1종 데이터 입력
- `1-1`부터 `1-20`까지 고정 초반 스테이지 데이터 입력
- `1-20` 이후 스테이지는 챕터당 20개씩 절차 생성

초기에는 코드 배열로 시작해도 된다. 단, 몇 년 플레이를 가정하면 스테이지를 수동 테이블로 늘리는 방식은 유지보수 비용이 커진다. 장기 진행 구간은 공식 기반 생성으로 두고, 이벤트/특수 챕터만 별도 데이터로 덮어쓰는 구조가 낫다.

## 3단계: 스테이지 진행 시스템

완료 기준:

- 현재 스테이지 ID를 관리한다.
- 최고 도달 스테이지 ID를 관리한다.
- 진행 모드를 관리한다.
- 일반 스테이지 클리어 시 자동 진행 모드에서는 다음 스테이지로 이동한다.
- 선택 반복 모드에서는 같은 스테이지를 다시 시작한다.
- 보스 실패 시 `BossBlocked` 모드로 바꾸고 같은 챕터의 19번 스테이지로 이동한다.
- 자동 진행 재개 버튼을 누르면 최고 진행 위치 기준으로 다시 진행한다.

## 4단계: 자동전투

완료 기준:

- 전투 시작 시 현재 스테이지 타입에 맞는 적 또는 보스 생성
- 영웅 최대 8명이 각자의 공격 주기마다 적 HP 감소
- 적 HP UI 표시
- 일반 적 사망 시 골드 지급
- 일반 적 처치 수 카운트
- 처치 할당량 달성 시 `StageProgressManager`에 클리어 통보
- 보스 스테이지에서는 30초 타이머 작동
- 보스 처치 성공과 시간 초과 실패를 구분

## 5단계: 골드와 레벨업

완료 기준:

- 골드 보유량 표시
- 영웅별 레벨 표시
- 영웅별 등급, 성급, 조각 표시
- 영웅별 공격력 표시
- 레벨업 버튼 구현
- 영웅 경험치 아이템이 부족하면 레벨업 불가
- 조각이 충분하면 성급업 가능
- 레벨업 후 보스 처치 가능성이 체감 가능하게 상승

## 6단계: 스테이지 선택 UI

완료 기준:

- `1-1`부터 최고 도달 스테이지까지 선택 가능
- 선택한 일반 스테이지는 반복 파밍 모드로 실행
- 선택한 보스 스테이지는 보스 재도전으로 실행
- 현재 모드가 자동 진행인지 반복 파밍인지 화면에 표시
- 자동 진행 재개 버튼 제공

1차 MVP에서는 스테이지 목록을 간단한 버튼 목록으로 처리한다. 맵 연출은 제외한다.

## 7단계: 뽑기

완료 기준:

- 1회 뽑기 버튼
- 10회 뽑기 버튼
- 확률에 따라 커먼, 언커먼, 레어, 에픽, 전설, 신화 결과 출력
- 등급에 맞는 영웅 중복 조각 지급
- 영웅별 조각 수와 성급 표시

주의:

신규 계정은 커먼 시작 영웅 6명만 기본 보유한다. 나머지 영웅은 뽑기에서 조각을 1개 이상 획득하면 보유 상태가 된다. 뽑기는 영웅 본체를 여러 장 지급하지 않고, 1회당 선택된 영웅 조각 1개를 지급한다.

## 8단계: 로컬 저장

완료 기준:

- 골드 저장
- 최고 도달 스테이지 저장
- 현재 스테이지 저장
- 선택 스테이지 저장
- 진행 모드 저장
- 보스 클리어 여부 저장
- 영웅 레벨 저장
- 영웅 조각 저장
- 영웅 성급 저장
- 재실행 후 데이터 복원

## 9단계: 오프라인 보상

완료 기준:

- 종료 또는 백그라운드 진입 시 마지막 접속 시간 저장
- 재접속 시 시간 차이 계산
- 최대 8시간까지만 보상 계산
- 현재 파밍 스테이지 기준으로 보상 계산
- 현재 위치가 보스면 직전 일반 스테이지 기준으로 보상 계산
- 오프라인 보상 팝업 표시
- 수령 시 골드 증가

## 확장 방향 반영 작업

이번 방향 변경은 다음 순서로 반영한다.

```text

5. 기본 장착 펫 1마리와 자동 공격 추가
6. 전장, 스킬 자동/피버 자동/가속 버튼, 지원 탭 UI 추가

8. 성장/뽑기/스테이지 알림 빨간 점과 사이드 아이콘 레일 추가

13. 영웅 편성 임시 편집, 저장 확인 팝업, 저장 후 스테이지 재시작 처리 추가

15. 영웅 일괄 승급 추가 - 조각이 충분한 모든 영웅을 가능한 성급까지 즉시 승급
16. 영웅 기본 스탯을 공격력/체력/공속/이속/패시브로 확장하고 A~Z/AB 없는 일반 숫자 표기 적용
17. 영웅 상세 정보 화면 추가 - 전투력, 경험치책, 스킬, 4개 기본 스탯, 5성/10성 해금 효과, 제외/레벨업/승급 버튼, 5개 장비 슬롯 UI
18. 영웅 상세 장비 탭 추가 - 기본 정보/장비/초월 하단 탭, 슬롯별 장비 목록 필터
19. 장비 뽑기 추가 - 장비 뽑기권/루비 소모, 장비 보유 수량/레벨/성급 저장, 소환 UI 결과 표시
20. 장비 장착/해제 UI 추가 - 영웅 편성과 동일한 `+` 선택, 슬롯 클릭 장착, `-` 해제, 장착중 표시와 영웅별 슬롯 저장
21. 전투 틱마다 공격 가능한 출전 영웅을 한 묶음으로 처리하고, 해당 묶음의 영웅들이 동시에 공격 모션을 보이도록 개선
22. 영웅 특성별 전장 배회 모션과, 몬스터/영웅이 최초 대상을 고른 뒤 사망 전까지 유지하는 타깃 락 이동 추가
23. 전장 액터 목표 좌표 직접 대입 제거 - 영웅 `MoveSpeed` 기반 보간 이동 적용
24. 상단 단일 몬스터 HP 게이지 제거 - 100마리 킬 진행바, 몬스터별 소형 HP바, 처치 수만큼 사방에서 재진입하는 몬스터 스폰 로직 추가
25. 계정 레벨/계정 경험치/특성 포인트와 영웅 특성 탭 추가 - 19뎁스 연결형 특성 트리, 연결된 이전 노드 MAX 해금
26. QA 러너와 밸런스 리포트 갱신
```

4배속 결제, 수동 스킬, 펫 성장, 몬스터 100개 실제 오브젝트 생성은 아직 구현하지 않는다.

## 10단계: MVP QA

확인할 항목:

- 첫 실행에서 오류 없이 `1-1` 자동전투가 시작되는가
- `1-1` 몬스터 100마리 처치 후 `1-2`로 자동 이동하는가
- 일반 스테이지 선택 시 같은 스테이지만 반복하는가
- 보스 스테이지에서 30초 타이머가 작동하는가
- 보스 실패 시 같은 챕터 19번 반복 파밍으로 돌아가는가
- 자동 진행 재개 시 다시 보스 도전이 가능한가
- 골드가 음수가 되지 않는가
- 저장 후 재실행해도 진행 모드와 스테이지가 유지되는가
- 기기 시간을 조작했을 때 오프라인 보상이 비정상적으로 커지지 않는가

## 리스크

| 리스크 | 이유 | 대응 |
| --- | --- | --- |
| 보스 실패 구조가 없으면 성장 목표가 약함 | 유저가 왜 파밍해야 하는지 명확하지 않음 | `1-20` 보스 관문을 MVP에 반드시 포함 |
| 선택 스테이지 반복과 자동 진행이 섞임 | 상태 관리가 꼬이면 진행 버그가 쉽게 생김 | `ProgressMode`를 명시적으로 둔다 |
| 밸런스가 너무 빠르게 무너짐 | 방치형은 수치 증가가 핵심이라 작은 공식 차이가 크게 벌어짐 | 초반 20스테이지는 수동 조정, 이후는 성장/보상 공식을 코드와 문서에 고정 |
| UI 작업량 증가 | 수집 RPG는 버튼, 팝업, 목록이 많음 | 1차 MVP는 한 화면 중심으로 제한 |
| 뽑기 복잡도 증가 | 천장, 픽업, 중복, 등급 연출이 붙으면 커짐 | 등급 확률, 조각, 성급업까지만 구현 |
| 저장 구조 재작업 | PlayerPrefs는 확장성이 낮음 | MVP 이후 JSON 저장으로 이전 |

## 다음 결정 사항

아직 결정해야 할 것은 다음이다.

- 보스 실패 후 자동 재도전 버튼을 둘지, 자동 진행 재개 버튼만 둘지
- 스테이지 선택 UI를 목록형으로 유지할지, 간단한 챕터 맵으로 확장할지
- 특성 포인트 지급량과 계정 경험치 곡선을 현재 속도로 유지할지
- 장비 스탯을 전투력/전투 계산에 어느 시점부터 강하게 반영할지
- 임시 도형 캐릭터를 SD 캐릭터 스프라이트 파이프라인으로 교체하는 기준
- 게임명
- 세계관 톤: 판타지, 현대, SF 중 선택

이 결정들은 1차 MVP 구현을 막지는 않는다.

## 레퍼런스 반영 후 수정된 우선순위

새 레퍼런스 기준으로 성장과 뽑기 구조가 확장되었다. 하지만 전부 바로 구현하면 MVP가 흐려진다.

다음 구현에서는 아래 순서만 반영한다.

```text
1. CurrencyWallet을 gold, ruby, heroExpItem, heroSummonTicket 지원으로 확장 - 완료
2. 영웅 레벨업 비용을 gold에서 heroExpItem으로 변경 - 완료
3. 전투 보상에 heroExpItem 소량 지급 추가 - 완료
4. 계정 능력 성장 데이터 추가 - 완료
5. 공격력, 체력, 치명타, 더블 치명타, 최종 데미지 성장 7종으로 확장 - 완료
6. 성장 레벨업 단위를 1x/10x/100x/1000x로 선택 가능하게 변경 - 완료
7. 영웅 뽑기는 heroSummonTicket 우선, 부족하면 ruby 소모로 변경 - 완료
```

이벤트 뽑기와 룬 뽑기는 구조만 고려한다. 장비 뽑기는 장비 보유 수량/레벨/성급 저장과 영웅별 장착/해제 UI까지 구현하고, 강화 UI와 스탯 전투 반영은 별도 단계로 둔다.
## 완료: 토템 강화

구현 목표는 토템을 프리셋 장착물에서 전역 장기 성장축으로 바꾸는 것이다. 룬/장비와 역할이 겹치지 않도록 장착 슬롯을 폐기하고, 기본 6개 카테고리 효과가 항상 모두 적용되게 한다. 진화는 개별 토템 승급이 아니라 같은 등급 6종을 모두 Lv.100까지 올린 뒤 전체가 다음 등급으로 넘어가는 구조로 간다.

작업 범위:

1. `TotemDefinition`, `TotemState` 추가
2. `GameData`에 전투/수호/지원/비전/폭풍/지휘 6종 토템 등록
3. `CurrencyWallet`에 `TotemEssence` 추가
4. `SaveKeys`에 토템 레벨/등급/해금 키 추가. 기존 프리셋 장착 슬롯 키는 호환용으로만 유지
5. `BattleManager`에 토템 로드, 강화, 전체 진화, 전역 전투 계산 반영 추가
6. `GameHud` 편성 슬롯의 토템 장착 동작 제거
7. `GameHud` 영웅 하단 `토템` 탭 UI 추가
8. 같은 등급 6종 Lv.100 달성 전에는 전체 진화 비활성 처리
9. 디버그 버튼에 토템 정수 지급과 토템 기본 보유 처리 추가
10. Unity 컴파일 확인

후속 작업:

- 토템 정수의 실제 획득처를 스테이지 첫 클리어, 반복 보상, 던전 중 어디에 둘지 결정
- 토템 성급 또는 중복 획득 구조는 뽑기 경제 설계 후 추가
- 장기 운영 보상 곡선에서 토템 정수 공급량 검증
## 완료: 룬 페이지 1차 구현

룬은 영웅 탭 하단의 `룬` 페이지에서 합성과 정보 확인을 관리한다. 실제 장착은 편성 탭의 룬 슬롯 4개와 목록 모달에서 처리하고, 같은 룬은 한 프리셋 안에서 중복 장착할 수 없다.

1차 구현 범위는 다음과 같다.

- 룬 데이터 10종 추가: 검격, 처형, 방벽, 수확, 비전, 질풍, 정밀, 생명, 지휘, 재생
- 룬 레벨 제거, `RuneGrade`와 등급별 보유 수량 기반 합성
- 프리셋별 `heroFormation.{preset}.rune.{slot}` 저장
- 편성 탭의 저장 확인 후 룬 장착/해제를 영웅 변경과 함께 저장하고 스테이지 재시작
- 전투 계산 반영: 공격력, 최종 피해, 체력, 피해 감소, 골드, 경험치책, 계정 경험치, 공속, 이속, 스킬 피해, 스킬 쿨타임, 치명타 확률
- QA 디버그: 모든 기본 룬 보유 처리, 커먼 룬 지급

아직 제외한 범위는 룬 뽑기와 세트 효과다. 룬 등급은 넣되 레벨과 별도 조각 재화를 빼서 성장축을 줄이고, 합성 요구량을 크게 잡아 장기 수집 축으로 둔다.

   - 시설별 수령과 모두 획득 제공

4. 배치 로직
   - 출전 중인 영웅도 시설 배치 가능

5. 사냥 보상

   - 보스는 자재를 지급하고, 벽돌/철재는 스테이지에 따라 확장

6. UI

   - 배치 인력 모달은 시설별 행, 배치 영웅, 잠긴 슬롯, 추천 배치, 모두 해제 제공
   - 추천 배치는 기존 유효 배치를 유지하고 빈 해금 슬롯만 채움

7. 디버그
